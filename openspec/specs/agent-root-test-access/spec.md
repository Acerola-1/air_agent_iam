# agent-root-test-access Specification

## Purpose

按用户明确要求为当前既有 root 完成可审计的 Agent 全业务测试配置，通过普通企业角色与有效权限提供可验证的数据查看能力，并在联合切换后彻底清理旧授权残留且不创建备份副本。

## Requirements


### Requirement: 指定既有 root 的显式测试配置
配置 SHALL 精确定位现有root用户UUID，覆盖执行时明确列出的全部当前有效企业，为其创建缺失成员和企业专属测试角色，开通并授予当前注册Agent业务。保留现有账号及密码，不复活被停用或删除的主体，不配置未来资源通配授权。

#### Scenario: 首次配置与重复执行
- **WHEN** 现有有效root尚无业务角色，执行明确目标清单的配置命令并再次执行
- **THEN** 各目标企业具有一条合法成员关联及明确角色授权，重复执行不重复创建、不重复推进无变化修订

#### Scenario: 身份冲突或停用
- **WHEN** root不存在、同名身份冲突、目标企业无效或现有root成员被显式停用
- **THEN** 写前报告冲突并停止，不另建root、不改密码、不隐式启用停用成员；报告保留未完成项

### Requirement: 全数据测试资格通过正常权限表达
root SHALL 在明确企业上下文内获得所有当前Agent业务使用权及Agent运营明细、指标、受控正文所需查看权限，通过真实身份查询可见。不因用户名绕过RLS、扩大其他成员或自动授予知识库权限；外部MCP数据范围由真实连接及服务端能力决定。

#### Scenario: root实际使用和查看
- **WHEN** root以正常登录及切企业流程进入目标企业
- **THEN** 实时身份含当前业务码及所需Agent查看码，可在其权限范围查看业务数据，其他企业须切换有效上下文

#### Scenario: root撤权反例
- **WHEN** 临时撤销root一项业务角色授权或回收企业业务
- **THEN** 同一root下一次核验失去该业务资格，不能靠平台管理员身份继续运行；恢复明确授权后可重新登录验证

### Requirement: 配置修改原子审计和最小波及
一次配置 SHALL 在每个目标企业内原子提交开通、成员、角色、授权、修订和审计，并以非秘密执行清单记录各企业结果。正常请求始终使用受限数据库身份；一次性配置不能成为开放的提权接口或每次启动自动重授任务。

#### Scenario: 中途故障
- **WHEN** 配置某企业时写权限或审计失败
- **THEN** 该企业事务回滚，已提交企业被如实记录；修复后仅补未完成项，不伪造跨库或跨企业全局原子性

### Requirement: 旧授权清理有明确范围且不留备份
最终交付 SHALL 物理删除实际存在的旧Agent Skill/MCP人员授权定义及关联、废弃专用表、兼容种子和本任务生成缓存，不创建dump、快照、备份表、影子库或改名旧表。通用IAM身份/角色/权限表、有效业务配置、审计及历史迁移不属于旧表；无残留时提交零项证明。

#### Scenario: 发现旧授权记录
- **WHEN** 新业务链路已验证，清单命中旧MCP授权码及角色引用
- **THEN** 只删除命中定义与关联、推进修订并审计，知识资源和正常角色不改变，旧码不再出现在身份或页面

#### Scenario: 无专用旧表
- **WHEN** 当前IAM未建过Skill/MCP专用授权表
- **THEN** 记录实际不存在，不为满足清理要求删除通用授权表或创建再删除假旧表

### Requirement: 联合交付状态真实
交付 SHALL 区分IAM权限配置、Agent真实运行、Agent数据查看和外部MCP范围验证，不以root权限列表代替查询结果。清理后需联合复验并证明无本任务备份副本；未证实的外部全数据能力不得标成完成。

#### Scenario: 外部授权尚未提供
- **WHEN** root正常业务运行成功，但外部服务没有可验证的全数据范围协议
- **THEN** 报告说明本系统权限已配好与外部范围未证实，后者作为独立限制保留，不伪造万能令牌
