# I4 正式切换前交接

本轮为独立 IAM 与 Agent 业务库物理拆分的代码和隔离候选验收；不是生产切换记录。原 IAM、Agent、RAG 的实际配置未修改，RAG 数据/索引未迁移。完整评分与证据见 `docs/reviews/i4-luna-independent-acceptance.md`，实施原报告按轮次保留。

## 启用顺序

1. 先备份并在隔离环境恢复真实 Java IAM 源和 Agent 源，记录真实四库身份/所有者、版本、依赖清单与 UUID 对账。未知 UUID、同名异 UUID、未知函数/视图/触发器/外键不得自动合并或忽略。
2. IAM 必须先部署包含 Flyway V23 的版本；旧 V22 会被最终 CLI 明确拒绝。Agent 源须正常升级至 Alembic `0020_i4_reference_cleanup`。local 源仍保留旧身份表，只有显式拆分目标才转换成纯业务库。
3. 为确实启用校准功能的 Agent 配置独立、持久登记的内部客户端，其 scopes 按实际用途明确登记 `identity:introspect`、`runtime-ticket:issue` 和 `tenant:status:read`。不要给所有客户端扩大权限；不要手工扩展启动引导管理的 runtime 客户端，其权限会在重启覆盖。独立管理的客户端不能同时由该 bootstrap 入口重写。只读校准密钥独立于用户运行票据密钥。
4. 把四个 DSN、预期 owner、受控 PG 工具入口和私有证据目录放到权限为0600的环境文件中；执行 inventory，先检查真实输出。使用实际数据库名/OID/集群标识/连接角色确认工具与驱动指向一致的四个资源，不凭容器名判断。不要在公开报告/命令参数中放口令或令牌。
5. 按最终 CLI 的帮助与同一个唯一 run-id 执行在线 snapshot，在正式维护窗口 freeze/drain，再 finalize。排空超时保持栅栏，不可人工跳过检查或开放未完成目标。保留源库、控制状态和私有归档。
6. 在目标实际通过正常业务、非owner A/B/无上下文拒绝、撤销/删除和历史数据对齐后，再另行决定应用流量切换。同步核对 Agent/RAG 的 IAM 地址和客户端登记；RAG 仅更新已验证地址和身份合同，不重写原文档、向量或图索引。

## 中断与回退

同一 run 的续跑必须先核对持久状态与真实四库绑定。进入 transform/publish 意图后不可重新覆盖恢复归档；已开放新目标后必须保全新写、撤销和删除标记。`recover --execute` 在当前实现中明确禁用；只读 recover 仅用于诊断，不能作为已批准回切。需要正式回切时应另做包含最新目标数据的方案并验收，不能直接改回旧 DSN。

隔离测试库、容器、端口和合成账号都不能直接作为生产配置。首次66分及修复1的79分固定；主控的方案、夹具、独立复验和本交接说明不算实施模型代码成果。
